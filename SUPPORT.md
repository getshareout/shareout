# Support

ShareOut is maintained by one person ([@leorfer23](https://github.com/leorfer23)).
There is no dedicated support team and no SLA.

## How to get help

| Situation | Where |
|-----------|--------|
| Bug in the product or docs | [GitHub Issues](https://github.com/getshareout/shareout/issues) (use a template) |
| Feature idea | [Feature request](https://github.com/getshareout/shareout/issues/new?template=feature_request.md) — open an issue **before** a large PR |
| Security vulnerability | [SECURITY.md](SECURITY.md) — private advisory only |
| Install / deploy questions | [Install docs](https://docs.shareout.site/self-host/overview/) first, then an issue if still stuck |
| Contributing / setup | [CONTRIBUTING.md](CONTRIBUTING.md) |

## What to include in a bug report

- Self-hosted commit SHA (or approximate date) if not on latest `main`
- Steps to reproduce
- Expected vs actual behavior
- Relevant redacted logs (never paste `SESSION_SECRET`, API tokens, or OAuth secrets)

## Response expectations

Best-effort. Issues may sit for days or weeks. Security reports get priority
when triage capacity allows. Duplicate or incomplete reports may be closed with
a pointer to docs.
